# Общий план MeshPN: Waveshare P4 и Stamp-P4 + AddOn C6

Обновлено 29 октября 2026. Общая реализация сети, админки и VPN; аппаратные
профили раздельные. XIAO остаётся целью регрессионной сборки.
[История прежнего плана](plan-history.md), [подробный план VPN](plan-vpn.md).
[Ночная программа с двумя P4](plan-night.md): взаимный AP+STA стенд,
оптимизация, длительная проверка и восстановление; запуск по команде пользователя.

## Что готово и что подтверждено

| Область | Waveshare ESP32-P4-WIFI6 | Stamp-P4 + AddOn C6 |
|---|---|---|
| Сборка ESP-IDF 5.5.5, P4 v1/v3 | Собирается; v1 работала на плате | v1.3 проверена на плате; v3 пока только сборка |
| USB HS NCM + CDC, STA/AP, DHCP/NAPT/DNS | Работали на Mac/телефоне | USB HS и AP-интернет на телефоне подтверждены; AP b/g/n HT20 дал 12/11 Мбит/с |
| Автопрошивка с проверкой MAC | Проверена ранее | Штатный HS app→ROM→flash→app проверен |
| Раздельные USB/AP-сети и mDNS | 10/11, dongle.local | 12/13, dongle-stamp.local; установлено и проверено |
| AP+STA длительно под нагрузкой | Историческое зависание ещё не закрыто; сейчас пользователь сообщает работающий AP | Отключение 11ax только у AP убрало массовые потери в коротком тесте; длительная приёмка впереди |
| TCP/UDP/WireGuard, raw TLS | Реализованы; новая проверка CA требует аппаратной приёмки | Общая реализация; аппаратной приёмки нет |
| Captive portal без uplink | DNS/HTTP проверены; автоматическое окно телефона ещё не подтверждено | Пользователь подтвердил работу на телефоне |

Значение 480 Мбит/с — скорость USB, а не интернета. Полученные раньше
35–40 Мбит/с через Waveshare USB+STA не являются обещанием для AP+STA или VPN.

## Ближайшие работы

1. **Одновременная разработка двух P4.** Раздельные defaults сети/mDNS,
   выбор модели в тестах, отказ при неоднозначности, MAC-привязка для прошивки.
   Код и offline-проверки готовы; Stamp подключён, раздельные сети работают.
   Продолжить совместную приёмку по [инструкции](docs/multi-board.md). Сохранённые имена NVS
   не менять автоматически.

2. **Waveshare: завершить DIRECT AP+STA приёмку.** Один ограниченный прогон
   USB+STA как контроль, затем AP+STA с телефоном и синхронной телеметрией.
   При зависании сначала сохранить STA/AP/SDIO, память, ошибки TX, DNS,
   доступность IP и админки; сброс — после снимка. Повторять испытание после
   изменения, объясняющего наблюдение, а не ради ещё одного speedtest.
   Критерий: 30 минут обмена без зависания/ребута, восстановление после нагрузки.
   Восстановление после обесточивания и смены USB не доказывает исправление:
   [наблюдение 27 октября](reports/2026-10-27-p4-evening-observation.md).

3. **Waveshare: аппаратная проверка нового raw TLS.** Согласовать работающий
   exit --type=tls --tls-raw, CA и server name. Проверить свежие TLS-соединения,
   HTTPS через туннель, нагрузку, отключение exit и kill switch, неверные CA/имя.
   Без рабочего exit можно выполнять host-тесты, но нельзя объявлять аппаратную
   совместимость подтверждённой. После TLS — короткая общая регрессия
   TCP/UDP/WireGuard с сохранением профилей.
   [TLS инструкция](VPN.md#experimental-raw-tls), [offline отчёт](reports/2026-10-28-tls-trust.md).

4. **Админка и первичная настройка на телефоне.** Подтвердить именно
   автоматическое captive-окно без сохранённого/доступного Wi-Fi, подключение
   к сети из него, закрытие setup-режима, переименование и доступ USB/AP/STA.
   Уже выполненные DNS/HTTP/mDNS проверки заново без причины не повторять.

5. **Stamp: продолжить аппаратную приёмку.** Первый запуск выполнен:
   v1.3, MAC-привязка, C6 SDIO, HS NCM, STA, админка и интернет; исправлены
   duplicate START и OOM Diagnostics. [Отчёт](reports/2026-10-29-stamp-first-boot.md).
   Пользователь подтвердил NCM, имя и captive на телефоне. AP-интернет был
   почти недоступен (0.56/0.11 Мбит/с); синхронная телеметрия показала backpressure
   C6 и истечение TX, без STA disconnect. AP b/g/n HT20 восстановил немедленное
   открытие сайтов и 12/11 Мбит/с без массовых потерь; этот режим теперь default
   Stamp. STA сохраняет 11ax. Осталась длительная DIRECT/AP+STA проверка;
   [расследование](reports/2026-10-29-stamp-ap.md). VPN — после неё.
   Отдельно провести три контролируемых цикла автопрошивки с наблюдением uptime
   соседней Waveshare. C6 сообщает ESP-Hosted **2.12.1**; C6 не перепрошивался.
   Не переносить GPIO/reset Waveshare.
   [Аппаратный чеклист](docs/m5-stamp-p4-c6.md).

## Далее

- Wi-Fi 6: C6 работает только на 2,4 ГГц. Текущая точка не подтверждает AX;
  проверка фактического AX и сравнение скоростей ждут подходящей точки.
  Настройки роутера без запроса не менять.
- Аутентификация клиента raw TLS на exit; текущая проверка CA защищает
  подлинность сервера, но не заменяет контроль доступа клиентов.
- Профилированный TLS с проверкой JA3/JA4 на новых соединениях,
  transparent/combo и выборочная маршрутизация — отдельные этапы плана VPN.

## Правила проведения

Wi-Fi Mac не переключать. Stamp подключён и привязан; выбирать его по MAC.
Сборки в одном checkout последовательные.
При USB busy до 20 попыток через 30 секунд с тем же MAC, затем запрос
ручного действия; на соседний порт не переходить. Отчёты — файлами с board/build,
типом пути и условиями; результаты USB, AP, WAN и VPN не смешивать.
