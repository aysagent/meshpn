# Две P4 в одном окружении — offline проверка

Дата: 2026-10-28. Платы не перечислялись/не открывались, прошивки не записывались,
Wi-Fi Mac не переключался. Аппаратная проверка Stamp ожидает подключения.

## Изменения

- Waveshare: USB 192.168.10.1/24, AP 192.168.11.1/24, dongle.local.
- Stamp: USB 192.168.12.1/24, AP 192.168.13.1/24, dongle-stamp.local.
- STA получает адрес по DHCP. Имя по умолчанию задаётся профилем сборки;
  NVS пользовательского имени сохраняется. Загрузка default проходит ту же
  нормализацию, что и ввод через админку, без неограниченного strcpy.
- mDNS HTTP/HTTPS instance наследует hostname (проверено в используемом
  espressif/mdns); отдельное общее имя сервиса код не задаёт.
- Общий каталог development.json и --board/BOARD в performance/local-lab
  инструментах. Убраны проверки, привязывавшие эти инструменты только к Waveshare.
- Исправлен discoverBoard: явный admin-url больше не проигрывает found[0].
  При недоступности выбранного адреса нет fallback; при неоднозначности без
  выбора нет логина; модель сверяется на каждом status, USB/AP связаны сессией.
- monitor.sh не выбирает первый порт при нескольких; поддерживает BUILD_DIR
  для ELF конкретной сборки. Механизм безопасной прошивки по MAC не менялся.
- Общий актуальный план в plan.md, старый сохранён в plan-history.md.
  Инструкция одновременной работы — docs/multi-board.md.

## Проверки

- BUILD_ONLY=1, последовательно: Stamp P4 v1/NCM, Waveshare P4 v1/NCM,
  XIAO ESP32-S3/NCM — успешно, ESP-IDF 5.5.5.
- Проверены итоговые sdkconfig обеих P4: раздельные адреса и hostname,
  а не только содержимое defaults.
- Полный scripts/test-host.sh — успешно, ASan/UBSan для C-проверок.
  Тест hostname выполнен с обоими factory defaults и сохранением custom NVS.
  Flash identity suite: 46 проверок. Python path soak: 11 проверок.
- Полная группа performance JS: 59/59. Новый сценарий имитирует две P4:
  выбор Stamp независимо от порядка интерфейсов, явный URL, отсутствие login
  при неоднозначности/недоступности выбранной платы, отказ при неверной модели,
  отсутствие отправки сессии Stamp на Waveshare.
- bash -n monitor.sh, node --check изменённых standalone runner, git diff --check.

Артефакты сборок:
- build-m5_stamp_p4_c6-ncm-3353756185-wg1
- build-waveshare_esp32_p4_wifi6-ncm-2315835351-wg1

Это не проверка реальной одновременной USB enumeration, mDNS на общей LAN или
скорости Stamp. Два одинаковых профиля всё ещё требуют разных подсетей/имён;
XIAO оставляет прежние defaults 10/11. Пользовательские одинаковые имена NVS
нужно развести через админку. Общие managed_components требуют последовательных
сборок в одном checkout; для параллельных сборок нужны отдельные checkout.
