# Проверка доверия TLS без платы — 28 октября 2026

Обычный транспорт `tls` проверяет цепочку CA, имя exit и срок действия сертификата
при каждом новом соединении. Протокол остался совместимым с JS exit
`--role=exit --type=tls --tls-raw`: TLS 1.2 и прежний IPv4 framing.
Аппаратная проверка этого изменения не проводилась, платы не прошивались.

## Изменения

- В админке TLS появился импорт публичного CA PEM и явное удаление CA.
  Настройки других транспортов сохраняются. Замена/удаление CA перезапускает
  включённый TLS; сначала проверяется возможность загрузить текущий VPN config.
- CA хранится отдельным NVS blob, максимум 8192 байта. Это не увеличивает
  многократно копируемую структуру VPN config и не использует ограниченный
  4000 байтами NVS string. Буфер загрузки CA выделяется в PSRAM; при ошибке
  выделения/чтения подключение не продолжается без проверки.
- Имя из сертификата обязательно; оно передаётся как SNI и проверяемое имя.
  CA/name/time проверяются до успешного завершения handshake. Старые TLS-профили
  без CA/имени требуют настройки после обновления.
- В `vpn.tls` доступны состояние CA/часов, результат последнего handshake,
  SDK/mbedTLS коды и X.509 flags. Это не заменяет `vpn.connected` и internet probe.
- Использован существующий SNTP bootstrap. Без часов — `wait_time`.
  В ESP-IDF 5.5.5 проверка дат сертификата по умолчанию отключена: она включена
  явно. Insecure fallback отключён. Compile-time guard запрещает сборку без
  проверки дат или с пропуском проверки сертификата.

## Проверки

1. Полный `scripts/test-host.sh` прошёл с ASan/UBSan: framing/routing/DNS,
   kill switch, очереди, USB, конфигурация, UI и прежние регрессии.
2. Новый `tests/test-vpn-trust.mjs` компилирует production trust store и
   `meshvpn_vpn_tls_connect`; ESP-TLS boundary адаптирован к настоящему host
   mbedTLS из закреплённого ESP-IDF. Node TLS listener работает только на loopback.
   Выполнены по три свежих handshake:
   - доверенный CA + правильное имя — успешно;
   - неверное имя — `certificate_name_mismatch`;
   - другой CA — `certificate_untrusted`;
   - истёкший сертификат — `certificate_expired`;
   - ещё не действующий — `certificate_not_yet_valid`.
   Также проверены отсутствие CA, неинициализированные часы, PEM validation,
   отклонение leaf/junk, round-trip CA bundle >4000 байт, ошибка хранения,
   удаление CA и отсутствие сетевого handshake при закрытом preflight.
   NVS в host-тесте — адаптер, не физическая flash.
3. `tests/test-vpn-tls-io.mjs`: теперь VERIFY_REQUIRED + имя/CA; 128 IPv4 пакетов
   в duplex через реальные mbedTLS и production I/O wrappers/framer,
   с дроблением TLS records. Получено 128/128, повреждённых пакетов нет.
4. Production HTTP handlers: authentication, отсутствующее имя/CA,
   сохранение/ошибки, перезапуск только активного TLS, сохранность WG-настроек.
   Ошибка загрузки VPN config не меняет CA. UI сохраняет введённый PEM при ошибке
   и при polling, требует подтверждения удаления CA.
5. После review включён SDK date-check, CA переведён на blob и обработчик CA
   проверен на ошибку загрузки настроек. Соответствующие trust/API-тесты повторены
   успешно. Финальные P4/XIAO сборки прошли. В обоих sdkconfig проверены date-check=y,
   insecure fallback=n и external mbedTLS allocator. P4 app: 0x13ac40
   (59% раздела свободно); XIAO: 0x1470e0 (57% свободно).

## Что ещё не подтверждено

Это host-проверка политики и протокола с cross-build, не замер heap/стека/скорости
на ESP32. После подключения платы нужны импорт CA, соединение с реальным exit,
LAN HTTPS и отказ на неправильном CA/имени с сохранением kill switch.
Raw exit пока не аутентифицирует клиентов; exporter/Bearer/HTTP handshake и
профилированные JA3/JA4 не добавлены. SNTP не является аутентифицированным временем.
Нестабильность AP+STA не считается исправленной этой работой.
