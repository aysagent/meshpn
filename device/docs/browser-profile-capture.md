# Захват браузера и выбор профиля на плате

**Основной способ — кнопка в админке самой платы.** Телефона, подключённого к её
USB Ethernet или AP, достаточно; внешний сервер, интернет, установка сертификата
и перенос JSON не нужны. Нужна сборка `PROFILED_TLS=1`.

1. Открыть админку по настроенному имени `.local` в обычном браузере телефона
   (например, `http://dongle-stamp.local`). Не использовать окно captive portal:
   его сетевой профиль может отличаться от основного браузера.
2. В VPN выбрать `boring-tls`, указать **Profile name** и нажать
   **Capture this browser on device**.
3. Плата захватит реальный TLS ClientHello браузера, проверит воспроизводимость
   JA3/JA4 и сохранит поддержанный профиль в свой каталог. Он появится выбранным
   в **Browser profile**. Неподдержанный профиль отклоняется с объяснением.
4. Нажать **Save and apply**, чтобы применить выбор вместе с настройками VPN.
   Сам захват не включает VPN и не меняет работающий туннель.

### Как работает локальный захват

Браузер отправляет ClientHello до получения и проверки сертификата сервера.
Админка создаёт скрытое HTTPS-подключение к временному порту самой платы.
Плата принимает только первый ClientHello, закрывает соединение **без отправки
сертификата или иных TLS-данных**, затем сохраняет результат через авторизованный
запрос админки. Ошибка незавершённого TLS-подключения остаётся внутри скрытого
iframe; основная страница не переходит на страницу ошибки сертификата.

Временный listener привязан к локальному IPv4 текущей админки и принимает только
IPv4 инициирующего клиента. Он открыт максимум 25 секунд, обрабатывает до восьми
подключений, ждёт не более трёх секунд на одном. Максимум ClientHello — 8192 байта,
16 TLS records, 16 KiB входного потока. Кнопка **Cancel capture** закрывает ожидание.
Если вкладку закрыть, listener сам истечёт; без последующего авторизованного
опроса готовый профиль не записывается в NVS. Это привязка по адресу клиента,
а не аутентификация браузера внутри TLS: HTTP-запрос в capture-соединении не нужен.

Сборщик хранит сырой ClientHello только временно в PSRAM и очищает его после
разбора. Сохраняются структурные параметры и отпечатки, без random, key shares,
SNI или session ID. Пробный ClientHello выполняется на отдельном PSRAM worker.
При точном повторении профиля используется существующая запись; новое имя
при повторе не переименовывает старую. Перестановка расширений браузером может
дать другой профиль и занять новый слот.

## Каталог и применение

На плате четыре пользовательских слота плюс встроенный `chromium156-capture1`.
Профили неизменяемы по ID: повторный импорт того же ID отклоняется.
Удалить выбранный сохранённой конфигурацией профиль нельзя: сначала нужно
выбрать другой и сохранить настройки. Factory reset очищает каталог.
Ключ HMAC, CA и TLS server name остаются отдельными настройками и при импорте
или удалении профиля не меняются. Каждое новое подключение, включая повторный
ClientHello после HRR, сравнивается с выбранным профилем **до отправки TLS-байтов**.
Несовпадение закрывает соединение, без перехода к другому профилю.

## Границы поддержки

Это снимок JA3/JA4 **одного соединения**, не полная копия браузера.
В частности, Chromium переставляет расширения: следующий запуск может дать
другой JA3. Сохраняется конкретный порядок выбранного снимка.
HTTP-заголовки/SETTINGS, распределение GREASE, размеры записей, тайминги и
содержимое всех расширений не обещаются идентичными браузеру.
Идентификаторы trust anchors не копируются: расширение при наличии отправляет
пустой список, а доверие определяется отдельно сохранённым CA платы.

Текущая модель ограничена TLS 1.3 с объявленными версиями `[1.3, 1.2]`,
ALPN `h2` либо `h2,http/1.1`, EC point format `0`, Brotli certificate compression
(или его отсутствием) и ALPS codepoint 17613 для `h2` (или его отсутствием).
Массивы ограничены 32 элементами, key shares — четырьмя, JSON — 4096 байт.
Неизвестные поля/расширения, старый ALPS, другие compression algorithms,
недоступные ciphers/groups и невоспроизводимый отпечаток не подменяются
«ближайшим» профилем: захват показывает ограничение либо импорт отклоняется.
Формат JSON предназначен для платы; это не desktop/native helper profile.

Проверено без физических плат: настоящий Chromium 156 на обычной HTTP-странице
с production JavaScript админки, скрытое локальное TLS-подключение без сертификата
и внешней сети; production C/C++ parser, preview и независимая проверка JA3/JA4;
таймауты, отмена, ошибки памяти/каталога и сборки всех трёх плат.
Browser lab использует имитацию API/NVS; production сервис проверен отдельно.
На Stamp и Waveshare (bfa0756) дополнительно проверены реальная админка с Mac
Chrome, захват, сохранение в NVS, cancel/timeout, отказ при неверном JA3,
сохранность после прошивки и reboot. [Отчёт](../reports/2026-10-29-onboard-capture-hardware.md).
Проверка с телефона, в том числе Safari и через AP, ещё нужна.
Поддержка произвольного браузерного профиля не заявляется.

## Необязательный внешний инструмент для разработки

Внешний инструмент ниже оставлен для разработки и архивирования профилей;
для обычного захвата с телефона он **не требуется**. Его JSON можно вручную
импортировать через **Optional JSON import → Import browser profile**.
Перед импортом плата выполняет ту же проверку воспроизводимости.

Из корня репозитория:

```sh
npm run device:profile:capture -- \
  --cert=/path/to/fullchain.pem \
  --key=/path/to/private-key.pem \
  --name=capture.example.com \
  --host=0.0.0.0 \
  --port=9443
```

Команда выведет ссылку вида `https://capture.example.com:9443/capture/<token>`.
Откройте **эту ссылку** нужным браузером. Его профиль сохранится сразу; страница
покажет JA3/JA4, список сохранённых профилей и кнопку скачивания JSON.
Открытие ссылки в другом браузере добавит его профиль. Обновление в том же
TLS-соединении повторного снимка не создаёт.

Нужен DNS, указывающий на машину захвата, и сертификат, которому браузер доверяет.
TLS должен завершаться **в этом процессе**, а не в nginx/CDN/reverse proxy: иначе
измерялся бы ClientHello прокси. TCP forwarding без завершения TLS допустим.
Для запуска только на своей машине можно опустить `--host`: по умолчанию
слушается `127.0.0.1`. Сертификат всё равно должен соответствовать `--name`.
Команда не меняет firewall, DNS и системное хранилище доверия.

Каталог по умолчанию — `device/browser-profiles/`, исключён из git.
Можно указать `--store=/absolute/path`. Сохраняется максимум 32 снимка;
для освобождения места остановите сервис и перенесите ненужные JSON из каталога.
После перезапуска сохранённые профили остаются, а токен ссылки меняется.
Ссылку следует передавать только тем, кому нужен доступ к этому каталогу.
Сервис не выдаёт необработанные ClientHello, session IDs, ключевые доли,
адреса клиентов или идентификаторы частных CA.
