# M5Stack Stamp-P4 + Stamp-AddOn C6 For P4

Профиль `m5_stamp_p4_c6`: ESP-IDF 5.5.5, ESP32-P4, 16 MiB flash,
32 MiB PSRAM, USB HS NCM + CDC, ESP-Hosted SDIO. Используется общий код
P4: USB/AP → STA, админка, DNS/DHCP/NAPT, TCP/UDP/TLS/WireGuard,
kill switch, диагностика и вход в ROM через CDC. 29 октября на реальном Stamp v1.3 подтверждены HS NCM на Mac, C6 SDIO, STA,
админка, интернет и штатная автопрошивка. Приёмка AP на телефоне и VPN ещё впереди.
[Отчёт первого запуска](../reports/2026-10-29-stamp-first-boot.md).

## USB и AddOn

Использовать **`USB2_HOST_DP` / `USB2_HOST_DM`**. Это выделенная пара HS PHY;
слово HOST в названии сети схемы не запрещает режим Device.
GPIO26/27 (`USB1_D-/D+`) — другой контроллер, только FS. GPIO24/25
(`USBC_D-/D+`) подключены к встроенному USB-C / Serial-JTAG.
Номера выводов модуля не являются номерами GPIO или выводов корпуса чипа.

Основание: [официальная распиновка M5Stack](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1218/S013-stamp-p4-pinmap.jpg),
[схема Stamp-P4](https://m5stack-doc.oss-cn-shenzhen.aliyuncs.com/1218/SCH_Stamp-P4_2026_03_16_17_23_06.pdf),
[USB PHY ESP32-P4](https://docs.espressif.com/projects/esp-iot-solution/en/latest/usb/usb_overview/usb_phy.html).

Самодельный USB-C разъём должен иметь корректные CC pull-down для Device,
общую землю и согласованную схему VBUS/питания. HS требует короткой корректно
разведённой дифференциальной пары. Нельзя просто соединять 5 V двух хостов.
Текущая USB-конфигурация рассчитана на bus-powered Device; для независимого
питания потребуется VBUS sensing по схеме конкретного подключения.
480 Мбит/с — скорость USB-сигнализации, не обещание скорости интернета.

SDIO через BTB-разъём AddOn (GPIO **на P4**):

| Сигнал | GPIO |
|---|---:|
| CLK | 43 |
| CMD | 44 |
| D0 | 45 |
| D1 | 46 |
| D2 | 47 |
| D3 | 48 |
| Reset / power enable | 42 |

Источник: [официальный пример Wi-Fi Stamp-P4](https://docs.m5stack.com/en/arduino/m5stampp4/wifi).
На AddOn RST управляет питанием; рабочий уровень — высокий. Не переносить
GPIO18/19/14–17/54 из Waveshare. GPIO35 — BOOT; управляемого обычного LED
в этом профиле нет. Логи направлены в Serial/JTAG встроенного USB-C.
HS CDC предназначен для автопрошивки; обычная сборка на нём не выводит логи.

C6 должен иметь совместимую **ESP-Hosted SDIO slave** прошивку. Версии host
зафиксированы в `dependencies.lock.esp32p4`; заводская прошивка AddOn пока
не проверена. Прошивка P4 не перепрошивает C6. При первом запуске проверить
SDIO INIT, версию coprocessor, scan/connect STA и AP. Если протокол не совпадает,
готовить C6 образ соответствующей версии отдельно, с его собственной проверкой
чипа/подключения. Автоматической записи в произвольный C6 нет.

## Команды из корня репозитория

```bash
# Только сборка, не перечисляет/не открывает USB-устройства:
npm run device:build:stamp

# При первом подключении приложения Stamp (один подходящий Stamp):
npm run device:bind:stamp

# Если первая установка начинается с ROM на выделенном HS-разъёме:
PORT=/dev/cu.<порт-ROM-Stamp> npm run device:bind:stamp

# Следующие прошивки: вход в ROM, запись, перезапуск, проверка USB identity:
npm run device:flash:stamp
```

ROM сам по себе не сообщает модель модуля. Поэтому для первичной привязки из
ROM порт выбирается явно, esptool читает eFuse MAC P4, ничего не записывая.
До установки нашей прошивки автоматический 1200-baud вход в ROM недоступен;
первая установка через HS ROM может потребовать BOOT/RESET. На проверенном
Stamp встроенный Serial/JTAG позволил войти в ROM через esptool usb_reset и
прошить без кнопок: явный USJ-порт, чтение MAC и проверка MAC в соединении записи.
Это отдельный первичный provisioning; CLI привязки пока выбирает HS app/ROM.
Привязка и автопрошивка этой
командой используют **HS-разъём**, встроенный Serial/JTAG остаётся для логов.
При двух неопознанных ROM-портах команда откажется угадывать.

По умолчанию образ рассчитан на P4 v1.x. Подключённый экземпляр Stamp — v1.3.
Для v3.x собрать и прошить отдельный образ:

```bash
P4_REVISION=3 npm run device:build:stamp
P4_REVISION=3 npm run device:flash:stamp
```

Не применять esptool `--force` для обхода проверки ревизии. IDF считает
v1/v3 несовместимыми; разные варианты имеют разные каталоги сборки.

## Несколько плат

- Stamp: `.board-binding-m5_stamp_p4_c6.json`, USB product `MeshPN Stamp-P4 HS NCM`.
- Waveshare: прежний `.board-binding-esp32p4.json`, команда `device:flash:p4`.
- XIAO: прежний `.board-binding-esp32s3.json`, команда `device:flash`.

Файлы привязки локальны и исключены из Git. Выбор P4 основан на модели и
уникальном USB serial из eFuse MAC. Перед записью MAC повторно читается в
том же открытом ROM-соединении, которое пишет flash. Имя `usbmodem` может
измениться: при переходе app → ROM отслеживается физический USB-путь.
`PORT` не отменяет проверки модели/MAC. Сборка содержит `meshvpn-board.json`:
ошибка модели, target или USB profile отклоняется до сброса платы. При сборке
также проверяются фактические TinyUSB mode/CDC/HS и семейство ревизии P4.
Конкурентные привязки сериализуются общей блокировкой в checkout; запись
публикуется целиком и никогда не перезаписывает появившуюся чужую привязку.

Проверка возврата CDC подтверждает старт USB-приложения, но не интернет/VPN.
При временном USB busy/исчезновении следовать принятому регламенту повторов:
до 20 попыток с интервалом 30 секунд, каждый раз с теми же проверками личности;
никогда не переходить на другую плату. Сам helper автоматически не меняет порт
на произвольный и не заменяет этот регламент внешнего оператора/агента.

Сетевые адреса Stamp: USB **192.168.12.1**, AP **192.168.13.1**,
STA DHCP, имя **dongle-stamp.local**. Waveshare сохраняет USB 192.168.10.1,
AP 192.168.11.1 и dongle.local. Пользовательское имя в NVS не перезаписывается.
[Одновременная разработка и выбор платы в тестах](multi-board.md).

## Вечерняя приёмка

1. Проверить ревизию P4, питание и HS-подключение; привязать MAC именно Stamp.
2. Прошить подходящий образ; убедиться в USB **480 Mb/s**, отдельном CDC и NCM.
3. Проверить SDIO INIT, STA DHCP, AP, админку по IP и `dongle-stamp.local`.
4. Сделать три повторные автопрошивки с подключённой второй платой;
   убедиться, что её порт/uptime не менялись.
5. Проверить USB Ethernet на телефоне, затем DIRECT throughput и стабильность.
   VPN — отдельный тест после базовой связности. Не считать заводской Wi-Fi
   режим C6 или совместимость iPhone подтверждёнными без этой проверки.
