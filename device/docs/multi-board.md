# Одновременная разработка Waveshare и Stamp

Обе платы используют общий код. Различия аппаратуры и начальной сети задаются
профилями сборки; рабочие результаты сохраняем отдельно по платам и build.

| Профиль | USB Ethernet | Wi-Fi AP | mDNS / DNS | STA | clean-vpn IPv4 |
|---|---|---|---|---|---|
| waveshare_esp32_p4_wifi6 | 192.168.10.1/24 | 192.168.11.1/24 | dongle.local | DHCP | 10.99.0.3 |
| m5_stamp_p4_c6 | 192.168.12.1/24 | 192.168.13.1/24 | dongle-stamp.local | DHCP | 10.99.0.4 |

Туннельные адреса фиксированы для TCP/UDP/TLS/boring-tls, должны совпадать
с peer-записями native exit. WireGuard сохраняет свой Address. XIAO использует
`10.99.0.2`. [Настройка exit](profiled-tls.md#exit-и-настройки).

После прошивки новые адреса выдаёт DHCP USB/AP. При старой аренде обновить
подключение клиента. Админка доступна по имени через USB, AP и STA; mDNS
публикует адрес соответствующего интерфейса. Имя экземпляра HTTP/HTTPS-сервиса
по умолчанию наследуется от hostname, поэтому оно тоже различается.

Имя меняется в админке и сохраняется в NVS. Обновление **не заменяет** сохранённое
имя: если на Stamp раньше вручную сохранили dongle, переименовать его в
dongle-stamp. Не задавать двум устройствам одинаковое имя на общей STA-сети.
У сети роутера также не должно быть пересечения с USB/AP-подсетями.

XIAO сохраняет прежние 10/11 и dongle. Эта матрица разводит именно две модели P4;
для второго экземпляра одной модели либо XIAO вместе с Waveshare нужны отдельные
подсети сборки и имя. Сетевые defaults скриптов находятся в
[boards/development.json](../boards/development.json); для изменённой сборки
передавать явный --admin-url/--admin-ip.

## Прошивка

Из корня репозитория:

```bash
npm run device:flash:p4      # Только привязанный Waveshare
npm run device:flash:stamp   # Только привязанный Stamp
```

Привязки раздельные: .board-binding-esp32p4.json и
.board-binding-m5_stamp_p4_c6.json в device. Выбор идёт по USB serial/eFuse MAC,
не по номеру usbmodem. Перед записью сверяются MAC в той же ROM-сессии,
модель сборки, чип и ревизия. Один MAC нельзя привязать к обеим моделям.
Первичная привязка неизвестного Stamp требует явного PORT и чтения MAC без записи;
подробности в [инструкции Stamp](m5-stamp-p4-c6.md).

При неоднозначности — отказ; перехода на соседнюю плату нет.
Прошивка одной платы при подключённой второй поддержана, но запускать две
сборки одновременно в одном checkout нельзя: managed_components общие.
Для параллельных сборок использовать отдельные checkout с собственными build.
Файлы привязок локальные; общая блокировка создания привязок действует внутри
одного checkout.

## Сетевые проверки

```bash
npm run device:perf:usb-local -- --board waveshare --out device/perf-results/wave-local
npm run device:perf:usb-local -- --board stamp --out device/perf-results/stamp-local
npm run device:perf:stability -- --board stamp --minutes 15 --out device/perf-results/stamp-stability
npm run device:perf -- user@SERVER --board stamp --paths usb
```

--board также поддерживают perf-wan-control.mjs, perf-p4-paths.py и
vpn-local-lab.mjs. Можно передать каноническое имя профиля или BOARD в окружении.
Для изменённых адресов: --board stamp --admin-url http://192.168.X.1/;
у Python path soak — --admin-ip, у local VPN lab — --gateway.

Явный адрес выбирает именно этот endpoint; если он недоступен, другая плата
не подставляется. Без выбора при нескольких найденных интерфейсах скрипт
останавливается до логина (это относится и к USB+AP одной платы).
После логина проверяется ожидаемая модель, при последующих чтениях — тоже.
USB/AP связываются общей сессией; запросы и нагрузка привязаны к локальному
интерфейсу. Для двух устройств одной модели один --board не является уникальным
идентификатором: нужны разные сети и явные адреса.

usb-diag.py при нескольких CDC требует --port; HTTP-адрес передаётся отдельно
через --host. monitor.sh также отказывается автоматически выбирать порт, если их несколько;
передавать PORT и BUILD_DIR соответствующей платы, чтобы декодировать её ELF.
Не запускать monitor/usb-diag на CDC, который занят прошивкой.

Эти команды не переключают Wi-Fi Mac. Проверка AP с телефона остаётся отдельной;
команду perf:ap-managed, которая специально переключает Wi-Fi, без явного
разрешения не запускать. Обновление обеих P4 с MAC-проверкой и независимый программный reboot проверены на аппаратуре; см. [отчёт](../reports/2026-10-29-onboard-capture-hardware.md).
