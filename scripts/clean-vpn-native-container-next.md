Оставшиеся границы: amd64 runner, явная host USB/Wi-Fi/DNS
интеграция и наблюдатель. Физическую работающую пару не изменяли.

Исходные требования:

1. Общий compose-проект: отдельные сервисы VPN и web/API, варианты client +
   admin, exit + admin и лабораторная пара. Объединения YAML недостаточно:
   ограниченный host broker должен управлять выбранным VPN-контейнером,
   применять конфигурацию, читать состояние/диагностику и выполнять rollback.
   Не передавать Docker/Podman socket веб-приложению. USB, Wi-Fi и host DNS
   требуют явной интеграции с Linux-хостом. Host-интеграция остаётся отдельной; контейнерным engine управляет
   ограниченный supervisor внутри его namespace.
2. Альтернативный Alpine runtime рядом с Ubuntu 24.04. Собирать engine,
   BoringSSL/nghttp2/Brotli под musl, не копировать glibc-бинарник из Ubuntu.
   Проверить Node.js на ARM64/amd64, сетевые утилиты, CA, TUN/netfilter, DNS,
   stop/crash/recovery, HTTP/1.1/H2, transparent/combo и реальные ClientHello.
   Размер измерить после сборки; не обещать размер базового Alpine или снижение
   RSS engine. Сохранить закрепление зависимостей и безопасный build context.
3. Ubuntu systemd/QEMU лабораторию ради Alpine runtime не переносить. Новую
   упаковку сначала проверить изолированно, работающую физическую пару не менять.

Критерий готовности: воспроизводимый совместный запуск и управление через
админку; тесты отказов и восстановления; сравнительный отчёт размера образов и
матрица архитектур, без заявлений о непроверенных сценариях.
