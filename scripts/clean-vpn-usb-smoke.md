# Сквозная проверка USB-клиента с Mac

После DHCP на USB Ethernet, из репозитория на Mac:

```sh
node scripts/clean-vpn-usb-smoke.mjs --interface=en20 --source=192.168.8.31 --gateway=192.168.8.1 --expected-exit=84.201.14.124
```

Подставить фактические USB-интерфейс/IP Mac, адрес платы и ожидаемый IP exit.
У Zero обычно gateway `192.168.7.1`, у текущей A7Z — `192.168.8.1`.
Скрипт проверяет наличие source на указанном интерфейсе. Нужны Node.js и
штатные `/usr/bin/curl`, `/usr/bin/dig`; root не нужен.

Системные маршруты, DNS, Wi-Fi, proxy, hosts и доверенные сертификаты Mac
не меняются. DNS-запросы привязаны к USB source и отправляются на плату;
HTTP(S) сокеты привязаны к USB-интерфейсу, адреса сайтов задаются через
`curl --resolve`. Проверка TLS не отключается. Временные файлы удаляются.

JSON содержит A/AAAA по UDP/TCP, HTTP/HTTPS, внешний IP обеих веток combo,
1 MiB download и 256 KiB upload. Сверяются source, ожидаемый exit и объёмы
передачи. Запросы ограничены временем/размером; по каждому сайту проверяется
не больше двух IPv4-адресов. Ошибка даёт exit code 1 и `status: failed`.

Это ограниченный smoke: HTTP 302 Яндекса означает ответ сервера, переходы
не выполняются. Скрипт не запускает браузерный Speedtest, не проверяет iPhone,
IPv6 forwarding, отсутствие всех утечек или аварийное восстановление.
Внешние сервисы могут отказать независимо от VPN; отчёт сохраняет адрес,
код ответа и ошибку каждой попытки для разбора. DNS AAAA проверяется как
запрос записи, сами HTTP(S) соединения в этом тесте используют IPv4.
