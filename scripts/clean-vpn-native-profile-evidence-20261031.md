# Профили в админке: конфигурация и доказательства

Host и container broker используют общий ограниченный каталог native-профилей.
Показываются SHA256 точного файла, выбор в конфигурации, проверка при импорте
и отдельные области packet HTTP/TLS и исходного application TLS relay.

Импорт по-прежнему сначала выполняет native `--check-config`, сохраняет файл
без автоматической активации и теперь записывает связанный с его SHA receipt.
Если файл впоследствии изменён, receipt не подтверждает новую версию. Старые
локальные файлы остаются доступными, но помечены без подтверждения проверки.
Симлинки, FIFO/каталоги, слишком большие и повреждённые документы каталог
не читает как профиль. Содержимое профиля ограничено 16 KiB, receipt — 2 KiB,
каталог — 256 файлов. Ничего не запускается при чтении каталога.

«Указан в конфигурации» не означает «проверен в работающем соединении»:
`runtimeVerified:false` и `browserEquivalent:false`. Receipt отражает принятие
файла загрузчиком при импорте, не подпись автора, аттестацию текущего engine
или wire-проверку. Локальный JSON также не доказывает происхождение из браузера.

Страница capture отдельно показывает количество образцов, готовность кандидата
и источник версии браузера (оператор/browser protocol). На главной странице
профиль сохраняется и выбирается отдельно; независимый tcpdump остаётся
источником подтверждения реального ClientHello. Профиль packet-ветки combo
не приписывается произвольным исходным TLS приложения в relay.

Диагностический экспорт включает только эти ограниченные metadata, без raw
профиля, UA/заголовков, cookies или секретов. Обновление установлено только
локально в исходниках; рабочая пара после ремонта не перезапускалась.

Проверки: 15/15 catalog/API/diagnostics/container unit tests, без пропусков;
реальный Chromium DOM проверил configured/saved labels, отсутствие заявления
о runtime equivalence, текущий combo transport и сохранение guard selection
между polling/применением. Mac network не менялся.
