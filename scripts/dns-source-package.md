# Пакет исходников для DNS-установки

Команда собирает проверяемый snapshot кода, который принимает существующая
[транзакция публикации](dns-deployment.md). Она **не устанавливает DNS**, не
вызывает sudo/systemctl, не читает ключи или клиентские JSON-конфиги, не отправляет
запросы и не меняет настройки. Запускать без sudo:

```bash
npm run dns:source-package -- --output=/absolute/path/new-dns-bundle
```

Родительский каталог должен существовать, а `new-dns-bundle` — отсутствовать.
Путь должен быть абсолютным, без `..`; output внутри исходного проекта запрещён.
Команда выводит JSON с каноническим `output`, числом файлов, размером кода и
`bundleSha256`. При повторном запуске существующий output не перезаписывается.
После ошибки возможна незавершённая копия; она не устанавливается и автоматически
не удаляется. Для нового запуска выбирается новый каталог.

Состав совпадает с прежней полной VM-сборкой: JS/MJS из `scripts/`, включая
вспомогательные модули и тесты. Пользовательские файлы из `device/`, конфигурации
JSON, ключи, native binaries и `node_modules` не копируются. Это пакет именно
проверяемого DNS-пути, не универсальная сборка всех транспортов clean-vpn.
Наличие всех файлов не заменяет интеграционный тест используемых entrypoints.

Перед и после копирования сверяется snapshot исходников. Отвергаются symlink,
hardlink, пустые/слишком большие code files и недопустимые имена. Ограничения:
512 code files, 1 MiB на файл, 16 MiB суммарно, 4096 просмотренных source entries.
Code files получают0644, каталоги0755; manifest публикуется последним. Готовая
копия проходит тот же inventory verifier, что installed loader. Ключи и клиентский
opt-in должны подготавливаться отдельной согласованной установкой.

`bundleSha256` идентифицирует содержимое, **не является подписью или разрешением
на root-запуск**. Пакет, собранный обычным пользователем, ещё не root-owned trusted
source для live publisher. Подготовка доверенного installer/bootstrap и его
CLI остаётся следующим шагом; вручную переносить этот каталог в `/opt/clean-vpn`
и включать службы по этой инструкции не требуется.

Для coupled/publication VM builder теперь вызывает эту же библиотеку упаковки,
а не собственный manifest renderer. Уже работающий прогон `meshpn-dns-vm-nSxWC2`
запущен с прежним builder из среза `012a4e3`; его результат не подтверждает
новую ветку упаковки. Проверки нового packager:11/11; вместе с VM protocol и
host-refusal:70/70. Smoke на полном дереве создал280 code files (2672577 байт),
и `--help` client/adapter выполнен из отдельного канонического output без repo
imports. Это не VM/lifecycle или live-пилот.

Общая Node-регрессия:2086/2086 PASS, без skips,
`/var/tmp/meshpn-acceptance-sH7etW/report.json`. После решения о простом DNS
по умолчанию этот packager относится к отдельной managed-интеграции и не
является условием обычного туннелирования DNS.
