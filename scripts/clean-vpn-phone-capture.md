# Автономная диагностика телефона через USB

На Radxa с уже установленным native VPN:

```sh
sudo bash scripts/clean-vpn-phone-capture.sh start 900
sudo bash scripts/clean-vpn-phone-capture.sh status
# При необходимости завершить раньше:
sudo bash scripts/clean-vpn-phone-capture.sh stop
```

После `CAPTURE_READY` в `boot-*/summary.txt` можно переставить USB с ноутбука в
телефон, открыть проблемные сайты, затем вернуть USB ноутбуку. Выделенный
systemd unit продолжает работу независимо от SSH и возобновляет запись после
перезагрузки (не более трёх запусков, с общим оставшимся бюджетом времени).
При завершении или `stop` автозапуск отключается; определение диагностического
unit остаётся установленным. `start` печатает
каталог результата. `stop` завершает только этот диагностический unit;
автоматическая остановка — через указанное время (60–1800 секунд, по умолчанию
900). VPN, Wi-Fi, DNS, маршруты и firewall скрипт не перенастраивает.

В каталоге `/var/lib/clean-vpn-phone-capture/run-*` с доступом только root:

- `boot-*/before.txt`, `boot-*/after.txt`: адреса, маршруты, правила и счётчики firewall,
  DHCP leases и состояние VPN;
- `boot-*/any.pcap*`: Linux any, включая вновь созданные интерфейсы,
  snaplen 256, четыре файла примерно по 4 MB на каждый запуск;
- `boot-*/timeline.txt`: каждые 10 секунд USB-счётчики, соседи и TCP-соединения;
- `boot-*/services.log`: журнал native engine, владельца маршрутов и dnsmasq за прогон;
- `boot-*/summary.txt`: время начала/завершения, готовность и ошибки записи.

Ротация заменяет старые пакеты при заполнении лимита. При интенсивном speedtest
лучше сразу закончить запись после воспроизведения ошибки. Snaplen 256 включает
заголовки, DNS и начальные байты payload; это приватный диагностический материал,
не обезличенный отчёт. Не публиковать архив целиком. Конфиги с ключами и пароли
админки скрипт не читает. Завершённые записи остаются для разбора.
