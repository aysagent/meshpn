# USB rescue candidate for Radxa

This is a separate, additive administration path, **not** an automatic reboot
rollback and not a substitute for UART. Do not reboot until a second SSH session
has actually authenticated over the USB cable. An active socket alone is not
proof of login or boot recovery.

Fixed deployment: `usb0`, MAC `02:00:00:00:00:02`, address `192.168.7.1/24`,
SSH port `2222`. Installation requires the existing USB interface already up
with exactly that IPv4 address. It refuses existing rescue files/units and an
occupied TCP port. No replacement of existing files is supported.
The live `sys-subsystem-net-devices-usb0.device` must also be active; a visible
interface without systemd/udev registration is refused before publication.

```bash
sudo env "PATH=$PATH" node scripts/clean-vpn-usb-rescue.mjs
sudo env "PATH=$PATH" node scripts/clean-vpn-usb-rescue.mjs --apply
```

The first command only inspects prerequisites and prints a plan. The second
publishes four new files, reloads systemd, enables and starts **only** the rescue
socket. It does not restart SSH on port 22, USB gadget, VPN, guard or networkd.
It does not modify firewall, routes, DNS, Wi-Fi, authentication settings or keys.
Publication is exclusive per file, **not** a four-file transaction: on an error,
stop and inspect the partial installation; do not rerun blindly.

The address helper refuses a different MAC or unexpected IPv4 addresses; if the
known address is missing at boot/device reappearance, it adds it and brings only
`usb0` up. No address flush, module reload, gadget recreation or default route.
The socket binds both the IPv4 address and the USB device, and is enabled for
multi-user startup and device appearance. None of the added units requires
VPN/guard/networkd or `network-online.target`.

SSH runs in inetd mode using the existing `/etc/ssh/sshd_config`, host keys and
authentication policy. Forwarding/tunneling and reverse DNS lookups are disabled
for this extra listener. Existing `Match LocalPort` rules can make authentication
on port 2222 differ from port 22, so an actual login is essential. No new password
or key is generated by the installer. `/run/sshd` is preserved; the original
daemon and its active sessions are not stopped.

From the **USB-connected computer**, keep the original session open and run:

```bash
ssh -p 2222 root@192.168.7.1
```

Check the host-key fingerprint against the known Radxa key; do not disable host
key checking. If the host needs a static USB address, use the already-known
`192.168.7.19/24`, with no gateway/DNS. This avoids depending on dnsmasq/DHCP for
recovery. The existing guard permits replies to this private subnet; unrelated
firewall changes could still block them.

Limits: the gadget must actually create `usb0`. Its existing startup script and
its `After=network.target` ordering are **not modified**, and may delay USB.
Failure of gadget/USB hardware, boot filesystem, SSH authentication, or systemd
itself is not recoverable by this mechanism. Real Radxa boot is a separate test.

Implementation references: systemd's [socket binding and inetd activation](https://github.com/systemd/systemd/blob/main/man/systemd.socket.xml),
OpenSSH's [sshd inetd mode](https://man.openbsd.org/sshd.8).

## Laboratory

```bash
node --test scripts/test-host-usb-rescue.mjs
node scripts/clean-vpn-usb-rescue-lab.mjs /absolute/passed-host-boot-artifacts /absolute/verified-qemu-tools/root
```

The runner clones the prior passed VM's guest filesystem into a new temporary
directory and boots QEMU with `-nic none`, no host shared filesystem or port
forwarding. The USB stand-in is a veth pair inside that VM. SSH keys and the test
account configuration are generated only inside the guest, not copied from the
host. These tests cannot emulate the real Radxa gadget or prove its cold boot.
It checks free space before building, and removes its own disposable images
after the run while retaining serial logs and the JSON report. The second boot
reconstructs the installed unit files in a fresh VM; it is not a power-loss or
storage-durability test of the real device.

Validated on 2026-10-02: 73 focused local tests passed; two NIC-less QEMU boots
passed 23 checks (14 installation, 9 preinstalled boot). Both exercised real SSH
public-key logins while guard startup failed and networkd was stopped, USB-only
binding before firewall activation, a working persistent nft guard, and interface
removal/recreation. The installation phase also checked port 22 and its daemon PID,
unchanged firewall/IPv4 routes, read-only plan, and refusal to overwrite installed
files. Artifact report: `/var/tmp/meshpn-usb-rescue-lab-eEcvxC/report.json`.
Guest systemd was 255 on x86-64; Radxa's systemd 252/ARM64 and gadget require the
separate real-device login/boot checks. Password/PAM login was not exercised by
the VM (fixture used public keys with PAM disabled).
