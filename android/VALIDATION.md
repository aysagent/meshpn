# Проверка Android TV client — 2026-11-12

Собран release APK `org.meshpn.client`, версия 0.1.7, `armeabi-v7a`, minSdk 23,
targetSdk 28. APK подписан локальным RSA-ключом; проверены подписи v1 (Android 6)
и v2. В manifest есть TV launcher, touchscreen не обязателен, backup выключен,
приложение не debuggable. Ключ подписи не входит в Git.

Выполнено:

- `android/build-apk.sh`: release-сборка, **65 JVM unit-тестов**, Android lint
  без ошибок. Оставшиеся warnings: русские строки в первой версии UI, размер
  TV vector banner и отсутствие x86/ChromeOS ABI. Play-only проверка target SDK
  отдельно отключена: этот APK предназначен для локальной установки.
- Embedded Android adapter в отдельном Alpine ARM64 контейнере без внешней сети:
  **2 матрицы HTTP/2 и HTTP/1.1**. Настоящий TLS, передача IPv4-пакетов в обе
  стороны (включая UDP/53), reconnect после смены generation, protect перед
  connect и каждым повтором, отказ protect, bounded stop/restart, сохранение
  владения переданным FD, отсутствие изменения stdio и process SIGPIPE handler.
  В каждой матрице отдельно отклонены неверные TLS-имя и PSK.
- Linux native regression: **2 матрицы H2/H1** с backpressure, reconnect,
  blackhole, service lifecycle, неверными именем/CA/ключом.
- Общий native CTest: **14/14**, без пропусков.

При переносе обнаружены и устранены API-23 отсутствие getifaddrs в неиспользуемой
transparent-ветке и недостаточный стандартный стек musl worker. Android worker
запрашивает 2 МиБ; Linux harness проверен с тем же размером.

Повторный аудит 0.1.1: исправлены повторный вызов JNI после ошибки загрузки
библиотеки, отмена во время её инициализации, блокировка UI на native-проверке
импорта, публикация импорта после начала VPN и обработка устаревших callback.
Добавлены откат неудачного сохранения, ограничение глубины JSON и общий
15-секундный срок результата HTTPS-проверки, включая DNS. При зависшем resolver
новые проверки не создают дополнительные потоки. Тесты используют подменённые
Context/SharedPreferences/native backend, не эмулируют Android framework.
Нативные матрицы и CTest выше выполнены при подготовке 0.1.0; C++ код в 0.1.1
не менялся. Подпись APK сохранена для установки обновления поверх 0.1.0.

Аудит 0.1.2: при неудачной записи SharedPreferences выбор/удаление сервера
и переключение TLS-профиля восстанавливают прежнее состояние в памяти;
файлы конфигурации при ошибке удаления сохраняются. Незавершённый импорт
нельзя выбрать. Добавлены четыре регрессионных теста.
У ARMv7 release-библиотеки проверены зависимости `libm.so`, `libdl.so`, `libc.so`:
все 189 обязательных импортируемых символов есть в NDK stubs API 23. Это
статическая проверка совместимости, а не запуск JNI на прошивке.
Настройки TUN сверены с [контрактом Android VpnService.Builder](https://developer.android.com/reference/android/net/VpnService.Builder):
дескриптор неблокирующий, IPv6 не разрешён. C++ в этой итерации не менялся.

**Не проверено на физическом Android:** загрузка JNI на прошивке проектора,
системный VPN consent, настоящий Android TUN/netd/DNS, IPv6 policy OEM, пульт,
автозапуск и скорость/память A33 при просмотре видео. Socketpair-тест UDP/53
проверяет передачу пакетов, не Android DNS resolution. Для этого нужны установка
APK и приёмка из README на самом проекторе. Эмулятор Android не запускался.

0.1.3 подготовлена после сообщения пользователя: системного окна разрешения
на проекторе нет, `onActivityResult` возвращает результат без подтверждения.
Причина пока не установлена. Добавлены метаданные прошивки/системного компонента,
ограниченный persistent trace, recheck фактического разрешения и сохранение
отчёта на app-specific external storage без root/ADB/системного picker.
10 тестов проверяют consent lifecycle (в том числе OEM result/prepare mismatch,
дублированный callback, recreation, ошибки этапов без exception messages);
5 — запись отчёта на несколько накопителей, отказ одного, отсутствие носителей,
повторную запись и конфликт целевого пути. Это JVM-тесты; настоящий Android
VPN-диалог и запись на SD проектора остаются непроверенными.

VPS/Radxa и сетевые настройки Mac этой работой не изменялись.

0.1.4: пользователь сообщил, что после восстановления системного VpnDialogs
VPN-разрешение получено, но возникают connect_deadline как через домашний Wi-Fi,
так и через hotspot, с браузерным профилем и без него. На стороне VPS не получено
подтверждения нового TLS-сеанса проектора. Сам exit и отдельный ключ проверены
независимым клиентом; это не проверяет Android-маршрутизацию. Причина таймаутов
ещё не установлена.

Добавлены автоматические TCP-пробы до/после TUN и отдельная явно привязанная
к физической сети проба при отказе после TUN. 7 новых JVM-тестов проверяют
реальный loopback TCP без отправки payload, закрытие сокета, отказ protect,
отмену до/во время подготовки, ошибку bind без раскрытия exception message,
запрет DNS-имён и неверных параметров. Всего 50 JVM-тестов и lint пройдены;
API, недоступные на Android 6, устранены по результату lint. Android framework
protect/bind и поведение на проекторе этими JVM-тестами не проверяются.
C++ не менялся; нативные матрицы повторно не запускались. Новая версия нужна
для получения данных с устройства, исправление таймаутов не заявляется.

0.1.5, 2026-11-12. Получен отчёт 0.1.4 с CINEMOOD / Android 6.0.1:
защищённый Java TCP к exit прошёл до TUN (149 мс) и после TUN (172 мс).
Native protect принят 9 раз без отказов, но попытки остановились в connecting
с connect_deadline, без handshake, TX/RX=0; браузерный профиль выключен.
Это локализует расхождение на TCP-пути, но не устанавливает конкретную причину
в Android/netd/kernel. Сеть и TLS-параметры не объявляются первопричиной.

Android-адаптер изменён: ограниченное по времени NIO-подключение через Android,
обязательный protect, явное дублирование подключённого сокета и передача его
владения native. BoringSSL, TLS-профиль, CA/имя/PSK и пакетный тракт не менялись.
Передача FD учитывает поведение fromSocket до API 29; исходник AOSP Android 6
также проверен: SocketChannel.close закрывает исходный FD, не делает shutdown
общей TCP-сессии.

Проверено: 52 JVM-теста + Android lint; 2 матрицы embedded Android adapter
(H2/H1) с настоящим TLS и передачей пакетов, неверными именем/PSK, reconnect,
отказом защиты, ошибками/таймаутом TCP, отменой сразу после передачи FD,
закрытием переданных сокетов и переводом host FD в неблокирующий режим.
Linux-стенд моделирует передачу сокета через dup и закрытие оригинала до TLS;
это не испытание ART/netd/ParcelFileDescriptor на физическом проекторе.
Успешное соединение проектора новой версией пока не подтверждено.

0.1.6: получен отчёт 0.1.5. Ранние Java TCP-пробы успешны (209/168 мс),
но реальные попытки тем же Java TCP-путём затем дают tcp_timeout до handoff/TLS.
Следовательно, предыдущая замена native connect на Java не решила отказ.
Различие семейства сокетов/языка само по себе больше не считается достаточным
объяснением; исходные настройки физического маршрута по ранней пробе доказать
нельзя. Принятый protect не заменяет явного выбора carrier для этого теста.

Добавлены обязательный bind exit-сокета к non-VPN Network, уведомление Android
об underlying network до establish и при каждой попытке, повторный выбор при
reconnect. Нет автоматического fallback к VPN/default при отсутствии физической
сети или ошибке bind. Диагностика фиксирует выбранную сеть, результат bind,
локальные адреса сокета и интерфейсов.

59 JVM-тестов и Android lint пройдены. 7 новых тестов проверяют исключение
VPN/default и противоречивых capability, выбор carrier, отсутствие физической
сети и выбор новой сети после потери старой. Loopback TCP-тест также проверяет
отчёт локального адреса. Это не Android framework-тесты; настоящий bind/netd
и соединение проектора пока не проверены. C++ после 0.1.5 не менялся, его
прошедшие матрицы повторно не запускались. Подпись APK сохранена.

0.1.7: отчёт 0.1.6 дал точное различие source IP: ранние пробы используют
192.168.1.16, реальные TCP к exit — 10.99.0.5, несмотря на network=100,
explicit_bind=true. То есть выбор Network не предотвратил выбор TUN-адреса;
конкретная неисправность OEM netd/kernel по одному отчёту не установлена.
Добавлены исключение exit /32 из VPN-маршрутов и явный source bind к carrier.
Проверка endpoint предотвращает расхождение enrollment/engine при исключении.

65 JVM-тестов и lint пройдены. Новые проверки: CIDR-покрытие без пересечений
и внешних дыр (границы IPv4 и 128 случайных exit), обработка loopback-ограничения
API 23, сохранение DNS/соседних IP в VPN, реальное TCP с явным source bind,
запрет default DNS при совпадении с исключённым exit.

Настоящий kernel regression в изолированном Linux-контейнере без внешней сети
получил: до исправления timeout/source=10.99.0.5; после установки плана из Java
кода приложения connected/source=192.0.2.2, также с явным bind. Адреса DNS
1.1.1.1/8.8.8.8 и соседи exit остались на tun0. Namespace удалены, контейнер
остановлен. Тест моделирует отсутствие эффективного обхода VPN через marks,
не исполняет Android VpnService/netd и не подтверждает подключение проектора.

Exit 84.201.14.124 проверен без изменений: контейнер healthy, независимый TLS/PSK
клиент 10.99.0.5 успешно получил DNS-ответы через оба upstream. Это не APK-тест.
Также обнаружены неверные часы: отчёт 0.1.6 датирован 2026-11-11 21:50:03 UTC,
раньше подготовки установленного APK (22:33:23 UTC). После TCP возможен отказ
auth_clock_skew. Добавлен переход к системной настройке часов и UTC в UI;
проверки сертификата и временного окна не ослаблялись. Часы пользователь должен
исправить на устройстве; root/ADB для самого приложения не требуются.
