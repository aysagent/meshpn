# Агенту: установить APK и разложить настройки на ФС Android

Комплект 2026-11-12: APK **0.1.4**, Android TV 6/API 23+, ARMv7.
Exit `84.201.14.124:443`; отдельный клиент **projector-android / 10.99.0.5**.
Транспорт `boring-tls`; TLS-имя `personal-cert.internal`; SNI `www.trustpilot.com`.
Профиль `chromium-156-bounded-cold-v1` включён. DNS `1.1.1.1`, `8.8.8.8`
через туннель. Kill switch отсутствует. Ключ предназначен одному устройству.

## Содержимое

- `clean-vpn-0.1.4-armv7.apk` — готовое приложение.
- `android-private/` — готовое дерево приватных файлов приложения: `ca.pem`,
  `psk`, `profile.json`, `bundle.json`, `engine.json`, `engine-base.json`,
  `shared_prefs/settings.xml`. В `client-id.txt` записано имя каталога UUID.
- `projector.bundle.json` — запасной вариант импорта через интерфейс приложения.
- `ca.pem`, `profile.json` — отдельные копии для проверки.
- `exit-verification.json` — результат настоящей проверки авторизации и DNS.
- `SHA256SUMS` — контрольные суммы файлов комплекта, кроме самого списка.

Архив содержит секретный клиентский ключ. Хранить приватно; содержимое PSK,
bundle и private directory не печатать в логи, не коммитить и не отправлять
в отчёт. Серверных закрытых ключей и ключей других клиентов в архиве нет.

## Порядок установки без ADB-скрипта

**Если приложение уже установлено:** передать новый APK на SD и установить обновление
поверх приложения штатным установщиком Android. **Настройки/ключи повторно
не копировать, приложение не удалять, данные не очищать.** Root для обновления
не требуется. Нажать «Подключить», подождать 20 секунд, затем «Сохранить отчёт на SD / память».
Забрать `clean-vpn-diagnostic.txt` по показанному пути. На доступной SD это
`Android/data/org.meshpn.client/files/diagnostics/clean-vpn-diagnostic.txt`.
Если SD не доступна приложению, копия будет во внутренней общей памяти;
её можно скопировать файловым менеджером либо через «Выбрать файл» в диагностике.
Системный logcat и причина сбоя чужого процесса в этот отчёт не входят.

Далее — только для первоначальной установки с доступом к ФС Android.
Агент работает своим доступным способом с ФС/консолью Android. Для прямой
записи в private directory нужен **root**; само VPN-приложение работает без root.
Не получать root обходом защиты. Если доступа нет — обычная установка APK и
импорт `projector.bundle.json` из интерфейса приложения.

1. Передать архив на проектор, распаковать в приватный рабочий каталог.
   Проверить `SHA256SUMS` на компьютере через `sha256sum -c SHA256SUMS`
   (macOS: `shasum -a 256 -c SHA256SUMS`). Проверить Android API >=23,
   поддержку `armeabi-v7a` и правильные дату/время устройства.
2. Установить APK штатным package manager: `pm install -r clean-vpn-0.1.4-armv7.apk`.
   Не удалять существующее приложение при ошибке подписи. Затем остановить его:
   `am force-stop org.meshpn.client`.
3. Дерево подготовлено **для основного Android user 0** и package
   `org.meshpn.client`. Убедиться, что `/data/user/0/org.meshpn.client` —
   настоящий data directory установленного приложения (на Android 6 может
   соответствовать `/data/data/org.meshpn.client`). Если используется другой
   Android user или data path, заменить абсолютные пути только в двух
   `engine*.json` перед размещением; `bundle.json` использует `@bundle/...`.
4. Выполнить из каталога комплекта с root-правами:

   ```sh
   APP=/data/user/0/org.meshpn.client
   ID=$(cat client-id.txt)
   APP_UID=$(stat -c %u "$APP")
   # APP_UID должен быть UID приложения, не 0. Проверить перед chown.
   test "$APP_UID" -ge 10000 || exit 1
   mkdir -p "$APP/no_backup/clients" "$APP/shared_prefs"
   test ! -e "$APP/no_backup/clients/$ID" || exit 1
   cp -R "android-private/no_backup/clients/$ID" "$APP/no_backup/clients/"
   ```

5. При свежей установке скопировать `android-private/shared_prefs/settings.xml`
   в `$APP/shared_prefs/settings.xml`. Если файл уже есть — сохранить резервную
   копию, поменять в существующем XML только `active` на `$ID`, `profile` на
   `true` и `autostart` на `false`; остальные настройки сохранить. Не копировать
   `.pending`, старые `settings.xml.bak` или служебные файлы из другой установки.
   При наличии `settings.xml.bak` у остановленного приложения сохранить его
   за пределами shared_prefs и убрать оттуда: Android иначе может восстановить
   старые настройки поверх подготовленного XML.
6. Выставить владельца и права: созданные каталоги `no_backup`, `clients`,
   каталог UUID и `shared_prefs` принадлежат `$APP_UID:$APP_UID`, режим `0700`;
   все файлы внутри каталога UUID и `settings.xml` — тот же UID/GID, `0600`.
   Не делать владельцем root и не использовать `chmod 777`.
   Восстановить SELinux-контексты штатной командой:
   `restorecon -R "$APP/no_backup" "$APP/shared_prefs"`.
   Если она не поддерживается/не исправляет контексты, не отключать SELinux:
   использовать импорт bundle через приложение.
7. Открыть `am start -n org.meshpn.client/.MainActivity`. Уже должен быть выбран
   `projector-android`, адрес `.5`, профиль включён. **Повторный импорт не нужен.**
   Нажать «Подключить» и подтвердить штатное системное разрешение VPN.
   Оно не задаётся XML-файлом; не обходить его через root/settings/appops.
8. После успешной проверки удалить временные копии архива/распаковки с общей
   памяти проектора. Приватные файлы установленного приложения оставить.
   Автозапуск включать через UI после первой успешной ручной проверки.

CA уже используется непосредственно VPN-приложением; не устанавливать его
в общесистемное хранилище сертификатов Android.

## Проверка и отчёт

- Статус «Подключён», растут счётчики; сайты и видео открываются в приложениях
  самого проектора. Внешний IPv4 должен быть `84.201.14.124`.
- Кнопка HTTPS-проверки, отключение/подключение, потеря и возврат Wi-Fi,
  затем перезагрузка с включённым автозапуском. После отключения VPN ожидается
  обычный интернет — kill switch нет.
- В отчёте: модель/прошивка/API, результат установки и этих проверок,
  диагностический отчёт приложения. Секретные файлы в отчёт не включать.
