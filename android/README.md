# Clean VPN для Android TV 6

Минимальный native-клиент `boring-tls`: Android 6/API 23+, ARMv7
(`armeabi-v7a`, в том числе Allwinner A33). Root не требуется. Устанавливается
локально APK, публикации в Google Play нет. Это клиент для приложений самого
проектора, не шлюз для других устройств.

## Установка и подключение

1. Установить `app/build/outputs/apk/release/app-release.apk` через файловый
   менеджер проектора (разрешить установку из неизвестных источников).
   При доступном ADB: `adb install -r app/build/outputs/apk/release/app-release.apk`.
2. Открыть **Clean VPN** в TV-лаунчере. Интерфейс работает стрелками пульта,
   OK и «Назад», без сенсорного экрана.
3. Нажать **Импортировать конфигурацию из файла** и выбрать клиентский bundle.
   Если прошивка не предоставляет системный выбор файла, есть **Вставить
   конфигурацию JSON**. Импорт проверяет CA, длину PSK и TLS-профиль native-кодом.
4. Нажать **Подключить**, подтвердить системное разрешение Android.
   Дождаться **Подключён**. Проверить сайт/видеоплеер и счётчики пакетов.

Поддержаны существующие форматы `clean-vpn-install-bundle` и
`clean-vpn-client-enrollment`. Из combo-bundle берётся **только boring-ветка**;
relay PSK и SSH clock identity не сохраняются. Нужен отдельный клиентский ключ
и адрес `10.99.0.2..254`: нельзя одновременно использовать bundle действующей
Radxa и проектора. Исходный Linux config с абсолютными путями не является bundle.

Если на exit уже инициализирован штатный
[реестр клиентов](../scripts/clean-vpn-native-clients.md), выделить проектору
новую идентичность можно там:

```sh
sudo node scripts/clean-vpn-native-clients.mjs add projector
sudo node scripts/clean-vpn-native-clients.mjs export projector --output=/root/projector.bundle.json
```

Для нестандартного каталога реестра добавить фактический `--directory` в обе
команды. **Не использовать `--address-discovery`**: первая версия APK требует
экспорт с уже назначенным `peer_ipv4`. Передать `projector.bundle.json` только
на проектор. Готовые отдельные client-N bundle из `install.sh` тоже подходят.
Этот Android-проект сам не меняет реестр/службы действующего exit.

## Возможности и ограничения

- До 8 сохранённых серверных конфигураций; выбор и удаление при остановленном VPN.
- Браузерный TLS-профиль из bundle либо обычный BoringSSL ClientHello.
  Профиль проверяет и воспроизводит **тот же C++ код**, что на Linux. Это не
  обещание полного совпадения сетевого поведения с браузером.
- DNS по умолчанию `1.1.1.1`, `8.8.8.8`. Запросы Android идут IP-пакетами через
  TUN → аутентифицированный туннель → exit. Отдельный локальный DNS-сервер,
  `SO_MARK`, iptables и Node.js в APK не нужны.
- При необходимости в объект **enrollment** можно добавить
  `"android_dns":["9.9.9.9"]` (1–3 IPv4-сервера, доступных через exit).
  Частная зона `.mpn`/порт 1055 из Linux DNS-relay в эту версию не перенесены.
- IPv4-only. Android блокирует IPv6, поскольку APK не разрешает это семейство
  и не вызывает `allowBypass()`. Проверка реального поведения OEM-прошивки
  входит в приёмку на устройстве.
- **Kill switch отсутствует.** После отключения, отзыва разрешения или гибели
  процесса Android возвращает обычную сеть. Во время переподключения живой
  службы TUN остаётся открыт: запросы могут временно ждать/теряться, прямого
  fallback для них приложение не делает.
- Повторное подключение при обрыве/смене сети, остановка вне UI-потока.
  Сокет exit защищается `VpnService.protect()` перед **каждым** connect.
- Необязательный автозапуск после загрузки после первого подтверждения VPN.
  Это `BOOT_COMPLETED`, не системный always-on; после force-stop приложение
  нужно открыть вручную. Прошивка может ограничивать автозапуск.
- Диагностика без ключей: состояние, ошибки TLS, счётчики, последние 120 событий,
  сохранение отчёта. HTTPS-проверка обращается к example.org через текущую сеть;
  HTTP-кэш отключён, но имя может разрешиться из системного DNS-кэша. Успех
  не доказывает свежий DNS-запрос или отсутствие утечек. Результат ограничен
  15 секундами, включая DNS; пока зависший системный resolver не вернулся,
  повторная проверка не создаёт новый поток. Изменение состояния VPN во время
  проверки делает её результат неактуальным.
- Время должно быть правильным. CA, TLS-имя и срок действия сертификата
  проверяются; автоматическая правка системных часов Android не реализована.
- Transparent/combo, exit, root-команды, веб-админка и внешняя страница захвата
  профиля в APK не входят. GPU для VPN не используется.

## Сборка

Нужны JDK 17 или 21, CMake, Git, patch, OpenSSL и Android SDK. Сборка нативных
зависимостей выполняется на компьютере, не на проекторе. Первой сборке нужна
сеть. Никакие host routes/DNS/firewall не изменяются.

Установить компоненты SDK через SDK Manager/Android Studio либо:

```sh
sdkmanager 'platforms;android-35' 'build-tools;35.0.0' 'ndk;27.2.12479018' 'cmake;3.22.1' 'platform-tools'
export ANDROID_HOME=/absolute/path/to/android-sdk
bash android/build-apk.sh
```

Скрипт конфигурирует закреплённый BoringSSL и применяет общие патчи, собирает
подписанный release APK, запускает unit-тесты и lint. `compileSdk=35`
не повышает требование к устройству: `minSdk=23`. `targetSdk=28` выбран для
локальной первой версии; Play-specific lint проверка target SDK отключена
отдельно. Остальные lint-проверки включены.

Подпись создаётся локально в игнорируемом `.tools/signing/`. **Сохранить оба файла
`release.p12` и `password`**: обновления поверх установленного APK должны иметь
ту же подпись. Не коммитить их. Gradle wrapper проверяет SHA256 дистрибутива.

## Архитектура и проверки

Java `VpnService` создаёт TUN, маршруты и DNS. JNI передаёт descriptor и
метаданные; пакеты не копируются через Java. Общий `native/clean_vpn/engine.cc`
в режиме `CVPN_ANDROID` дублирует переданный FD, не меняет stdio/сигналы процесса,
не открывает Linux TUN и не создаёт DNS listener. SIGPIPE блокируется только
на native worker и восстанавливается при выходе. Стек worker — 2 МиБ.

50 JVM-теста проверяют оба формата bundle, combo→boring, пути, base64,
размеры/глубину JSON, адреса/DNS, профиль, отмену загрузки native-библиотеки,
публикацию импорта, откат ошибок импорта/выбора/удаления конфигурации и настройки
TLS-профиля, ограничение HTTPS-проверки, цикл разрешения VPN и запись отчёта
при недоступном накопителе.
Context/SharedPreferences и native backend в этих тестах подменены:
это не Android instrumentation-тесты. Linux-лаборатория
проверяет **тот же embedded entry**, настоящий TLS/H2/H1, отказ авторизации,
protect до connect/при retry, передачу IP-пакетов, stop/restart и владение FD:

```sh
cmake -S native/clean_vpn -B native/clean_vpn/build -DCVPN_ANDROID_ADAPTER_TEST=ON
cmake --build native/clean_vpn/build --target android-adapter-test clean-vpn-engine-fixture --parallel 2
node --test scripts/test-native-android-adapter.mjs
```

Лаборатория моделирует TUN через socketpair; это **не** проверка Android
VpnService, Android DNS/netd, TV-пульта, OEM автозапуска или скорости A33.

Приёмка на проекторе: импорт → разрешение → подключение → DNS/сайты/видео;
отключение возвращает обычную сеть; 10 циклов connect/disconnect; потеря и
возврат Wi-Fi; сон/пробуждение; перезагрузка с включённым автозапуском.
При проблеме сохранить отчёт из приложения. Не отправлять файл bundle в логах.

## Если системное окно разрешения VPN не появляется

Начиная с 0.1.3: нажать «Подключить», затем **«Сохранить отчёт на SD / память»**.
Приложение покажет точные пути. Копии сохраняются на доступных Android-накопителях
в `Android/data/org.meshpn.client/files/diagnostics/clean-vpn-diagnostic.txt`.
На съёмной SD-карте агент может прочитать этот файл после подключения карты
к компьютеру. SD должна быть смонтирована Android и доступна приложению;
если доступна только внутренняя память, отчёт появится только там.
Root, ADB и разрешение на весь накопитель для этого не нужны: используется
[каталог приложения на внешнем накопителе](https://developer.android.com/reference/android/content/Context#getExternalFilesDirs(java.lang.String)).
Пункт «Показать диагностику» → «Выбрать файл» оставляет возможность сохранения
через системный диалог выбора файла; если его нет, используется запись выше.

Отчёт содержит модель/прошивку, компонент системного окна, доступные ограничения
пользователя, результат `prepare()`, код/время ответа и этап ошибки. Последние
24 события запроса сохраняются между перезапусками приложения. Ключи, bundle,
полные exception messages и чужой logcat не собираются. Отчёт может показать
момент отказа, но не внутреннее исключение системного VPN-диалога.

После любого ответа окна приложение снова вызывает
[`VpnService.prepare()`](https://developer.android.com/reference/android/net/VpnService#prepare(android.content.Context)).
VPN запускается только при фактическом разрешении. Это не обход подтверждения
и не обещание исправить отсутствующую в прошивке поддержку VPN.
Обновление устанавливать поверх прежнего APK; данные и разрешения не стирать.

## Если после разрешения идут connect_deadline

В 0.1.4 при каждом запуске добавлены TCP-проверки **только импортированного
exit IP:port**, до и после создания TUN. Сокеты в обоих случаях защищаются
`VpnService.protect`; если проверка после TUN не проходит, выполняется третья
через отдельно выбранную физическую сеть с
[`Network.bindSocket`](https://developer.android.com/reference/android/net/Network#bindSocket(java.net.Socket)).
Это отдельные диагностические соединения без TLS, PSK и полезной нагрузки.
Успешный TCP не означает успешную авторизацию VPN. Маршрутизация native-сокета
остаётся прежней; третья проверка не включает автоматический fallback.

На ожидание TCP каждой проверки отводится 3 секунды; при таймаутах запуск
может занять дополнительно до 9 секунд ожидания TCP. Проверки выполняются на
worker; отмена проверяется при сетевом ожидании не реже чем каждые 100 мс.
Время системных вызовов protect/bind зависит от Android. Результат проверки
не блокирует последующую попытку native-соединения.

Установить обновление поверх APK, нажать «Подключить», подождать 20 секунд и
сохранить отчёт. Он содержит точный exit, включение профиля, результаты TCP,
счётчики принятого/отклонённого protect для native, интерфейсы и типы сетей
до/после TUN. SSID, Wi-Fi-пароли, PSK и содержимое сертификата не собираются.
Эти результаты хранятся до следующего запуска VPN в текущем процессе;
сохранить отчёт до закрытия приложения. При смене Wi-Fi повторить подключение.
