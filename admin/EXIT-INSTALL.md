# Админка существующего exit на localhost

Это отдельная установка, не изменение USB-админки Radxa. VPN и его network
owner не перезапускаются. Новые web/broker services слушают только localhost
и приватный Unix socket; настройки DNS, маршрутов и firewall не меняются.

Сначала [инициализировать реестр клиентов](../scripts/clean-vpn-native-clients.md)
с engine/unit. Работающий engine должен поддерживать `peer_reload` и публиковать
стартовое `peer_reload_ready`: это подтверждает API именно запущенного процесса,
а не только нового файла engine на диске.

```sh
sudo node admin/exit-install.mjs --plan
sudo node admin/exit-install.mjs --apply
```

Для другого реестра добавьте `--directory=/private/clients`. Опционально:
`--name=main --port=18880 --capture-port=18843`. Все порты выше 1023, привязка
строго `127.0.0.1`; адрес публичного интерфейса параметром не принимается.

Установка создаёт отдельную системную учётную запись для web, приватные
настройки и два systemd unit с автозапуском. Web непривилегирован, broker root
для чтения credentials и ограниченных systemctl-операций; оба имеют пустой
capability set. `CAP_SYS_PTRACE`, Docker socket и доступ к произвольным командам
в API не предоставляются. Broker пишет только в свои state, реестр клиентов и
каталог выбранного exit config и выделенный replay directory для combo. Исходники и Node копируются в `/opt/meshpn-exit-main`.

Открыть на самом VPS: `http://127.0.0.1:18880/`. Для доступа с рабочего компьютера
можно использовать SSH port forwarding с тем же локальным портом:

```sh
ssh -N -L 18880:127.0.0.1:18880 root@YOUR_VPS
```

Сеть Mac этим установщиком не меняется; SSH forwarding — явное действие оператора.
Стандартный пароль `admin`; перед изменением клиентов требуется сменить пароль.
Экспорт комплекта содержит ключи выбранного клиента, не добавляется в историю
операций. Захват ClientHello использует отдельный loopback порт; для удалённого
использования ему также нужен явный SSH forwarding и корректное имя/доверие
сертификату. Обычные операции со списком клиентов от захвата не зависят.

Удаление служб:

```sh
sudo node admin/exit-install.mjs --remove
```

Удаляются только проверенные по hash собственные unit. Учётная запись,
исходники и настройки сохраняются для проверки; VPN и реестр клиентов остаются.
Повторная установка поверх существующих каталогов запрещена. Если установка
прервана, собственные опубликованные службы откатываются по возможности;
созданные приватные каталоги/аккаунт остаются для диагностики. Этот fresh installer
пока не является автоматическим updater существующей exit-админки.

## Приёмка

Три unit-теста планировщика и отдельный настоящий systemd-контейнер без uplink.
`admin/test/exit-install-systemd.mjs`: **9/9 для boring-tls и 9/9 для combo-tls** — localhost HTTP, вход/смена пароля,
реальный web→broker→manager→native reload, add/export/rotate/revoke, неизменность
PID VPN, нулевые web capabilities и удаление только admin services.
Первая попытка обнаружила EACCES при чтении `/proc/PID/exe` из ограниченного
broker. Вместо расширения прав добавлен startup API marker native и проверка
его journal по текущим PID/InvocationID. Повтор прошёл полностью.

Физический VPS этой установкой не менялся; приёмка выполнена в лаборатории.
